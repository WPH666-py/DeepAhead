## DeepAhead v0.5.7

**修掉"工具卡死拖死整轮 Agent"的三个根因；工具执行期间界面不再假死。**

---

## 🩺 现象：DSK 模式下 `read_image` 卡住，工作流都跑完了它还在那

日志停在「调用工具 read_image」，界面一直「思考中…」，看起来像前端卡了 —— 其实是**后端那一轮永远没返回**。
查到三个都能造成"永久挂起"的地方，全部修掉：

### 1. `read_image` 的视觉请求**根本没有超时**（本次根因）

`analyze_image` 之前用的是 `reqwest::Client::new()`，而 reqwest 的默认客户端**不带任何超时**。
视觉端点只要不返回（网络卡住、模型排队、代理吞连接），这个 `await` 就永久挂起，Agent 循环随之整轮卡死。

现在：连接超时 15s、整体超时 **180s**（OCR / 长文档识图确实可能跑一两分钟），
读响应体再加一层兜底；超时后给出可读的错误（含实际请求的 URL），交回给模型自己决定换方案。

### 2. `bash` 的 `timeout_ms` **从未真正生效**

旧实现是 `spawn_blocking(|| cmd.output())` 外面套一层 `timeout` —— 超时只是**不再等待**，
**子进程还在后台跑**，还占着线程。命令挂住时同样表现为整个 Agent 卡死。

现在改为 tokio 异步进程 + `kill_on_drop`：超时那一刻**真的杀掉子进程**，
默认上限从 30s 放宽到 **5 分钟**（长任务不再被误杀），并夹在 [1s, 30min] 内；
超时提示里告诉模型"这是长任务就拆小，或用 timeout_ms 显式放宽"。

### 3. 工具执行没有总闸

即使某个工具自己没写超时，也不该拖死整轮。Agent 循环现在给**每次工具调用**加了总上限
（默认 **600s**，子智能体与工作流阶段同样继承），到点中止并把原因回灌给模型。

## 💓 工具执行期间有心跳了

以前工具一进去就是黑箱：界面只能显示「思考中…」，用户无法判断是在跑还是死了。
现在后端每 20s 推一次 `tool_progress`，日志面板会滚动显示：

```
⏳ read_image 仍在执行（20s）
⏳ read_image 仍在执行（40s）
```

长任务一眼可见，不用再靠猜。

## 🔍 顺带修掉的隐患

- `vision::is_configured()` 走 `blocking_lock()` 读 tokio 互斥锁（在异步上下文里可能死锁），改为非阻塞快照；
- 视觉 Base URL 先做合法性校验，避免拼出非法 URL 才报错。

## 🔧 升级说明

- 这三个问题都只在"工具真的卡住"时才暴露，平时无感；升级后即使再遇到，也会**有明确报错并继续往下跑**，而不是整轮卡死。
- 回归测试：新增「bash 超时必须真的杀掉子进程」用例（用"睡 5 秒后写标记文件"验证进程确实被杀）。
