## DeepAhead v0.5.8

**子智能体不再"主流程都结束了还在跑"：它们会被父任务连带停掉，并且有各自的墙钟上限。**

---

## 🩺 现象：一个问题早就答完了，`subagents` 还在心跳

日志里能看到同一批 `subagents` 的心跳一路涨到 `仍在执行（780s）`，bash 的心跳也在旁边滚 —— 用户已经拿到答案了，后台还在跑。

原因有两层：

1. **子智能体是嵌套的子循环**：`subagents` 工具会在自己的调用里再起「子 Agent 循环」（独立上下文、最多 40 轮），父循环只能**等它返回**，中间没有任何取消通道；
2. **一个子任务能拖住整批**：`subagents` 内部是 `join_all`，只要有一个子任务不返回，整批都拿不到结果；
   叠加"工具调用没有上限"，就变成了"主流程结束、子智能体继续跑"。而且它们的文件改动和 bash 调用都在花你的 Token 和时间。

## ✅ 现在做成三件事

### 1. 取消信号贯穿父与子

`AgentLoopInput` 新增取消信号（共享 `Arc<AtomicBool>`）：

- 子智能体与父循环**共享同一个 flag**；
- 父循环的工具调用超时 → 置位 → 子循环在**下一次迭代**检查到并干净退出（日志留痕「收到取消信号，停止于第 N 步」）；
- 工作流阶段（DSK/DSA/DSF 的嵌套阶段）同样继承，整棵子树一起停。

**再也不会出现"父任务结束、子智能体还在跑"。**

### 2. 每个子智能体有自己的墙钟上限

`subagents` 里每个子任务单独设预算 = 父工具预算的 3/4（夹在 [60s, 300s]）：

- 某个子任务卡住 → 它单独判失败返回给模型（附原因「把任务拆得更小，或直接在主循环里做」），**其余子任务的结论照常返回**；
- 整批不再被一个慢任务拖死。

### 3. 工具调用上限收紧到 5 分钟

单个工具调用（含其内部派发的全部子智能体）默认上限从 10 分钟收紧到 **300s**：
超过 5 分钟基本已经偏离"给你解决问题"的节奏，此时中止并把控制权交还模型，比继续烧下去更有用。
超时那一刻会**同时置位取消信号**，把嵌套子循环一并带走。

## 💓 心跳现在能看清"是谁在跑"

嵌套层级会把标签带出来，日志里能分辨主循环与子智能体：

```
⏳ subagents 仍在执行（40s）
⏳ read_image（子智能体）仍在执行（60s）
```

## 🔧 升级说明

- 回归测试新增：取消信号在父子之间必须共享可见（守住"父停子停"的契约）。
- 如果你希望某个子任务跑更久：把它拆小，或直接在提示里让主循环自己做 —— 现在超过预算会被明确中止，而不是无限期挂着。
