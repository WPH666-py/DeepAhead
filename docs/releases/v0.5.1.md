## DeepAhead v0.5.1

本版是**界面重构 + 开关修复**：顶栏的 AI 入口改为「AI 驾驶舱」下拉，修掉了"裁决卡片 / 任务契约开关点了没反应"，并给规则引擎页补上保存按钮。

---

## 🧠 AI配置 → 「AI 驾驶舱」（下拉菜单）

顶栏原来两个并列按钮（AI配置、集成能力）合并为一个下拉：

```
🧠 AI 驾驶舱 ▾
   ├─ ⚙️ AI 配置       模型 / 视觉引擎 / API Key
   ├─ 📊 上下文占用     占用比例 / 窗口 / 压缩模式 / 引擎阈值
   └─ 🧩 集成能力       费用统计 · 上下文压缩 · 长期记忆 · 规则引擎 · 插件体检
```

- **「上下文占用」从 AI 配置里删掉了**，改为独立入口；原处那一整块（占用条、窗口输入、压缩模式、立即压缩）已移除。
- 独立的「上下文占用」窗口包含：实时占用比例与进度条、上下文窗口设置、压缩模式（手动/自动）、立即压缩，以及压缩引擎的关键阈值速览。

## ✍️ 主模型改回手动输入

Model 从下拉选择改回**文本输入**（保留 `datalist` 建议项，仍可自由填写）：

- 校验规则：名称**必须包含 `deepseek`**（大小写不限，`/deepseek/i`，因此 `deepseek` / `DeepSeek` / `DEEPSEEK` 都通过）。
- 输入时**实时提示**：识别为 DeepSeek 模型显示绿色确认，否则显示红色警告并说明保存时会被拒绝。
- 兼容代理前缀写法（如 `deepseek-ai/DeepSeek-V4`）。
- 保存时再次校验，不通过则拒绝并提示原因。

## 🐛 修复：裁决卡片 / 任务契约开关选不上

**根因**：Tauri v2 的 `#[tauri::command]` 默认 `rename_all = "camelCase"`，Rust 侧 snake_case 形参在 JS 侧必须用 camelCase 传。我此前从 JS 传的是 `turn_card_enabled`，而 Tauri 找的是 `turnCardEnabled` —— **参数匹配不上会被静默忽略**，命令照常返回成功，于是开关一勾就被后端返回值覆盖回 `false`，表现为"没法选择"。

已核对 Tauri 2.6.3 宏源码确认该约定（`ArgumentCase::Camel` 默认 + `key.to_lower_camel_case()`），并修复了两处同类问题：

| 命令 | 修复前（被忽略） | 修复后 |
|---|---|---|
| `rules_set_toggles` | `turn_card_enabled` / `task_contract_enabled` | `turnCardEnabled` / `taskContractEnabled` |
| `set_memory_config` | `enforce_weave` / `inject_weave` / `auto_ingest` / `fail_open` | `enforceWeave` / `injectWeave` / `autoIngest` / `failOpen` |

> 长期记忆页的四个开关此前也有同样的问题，一并修掉了。已在两处命令的 Rust 文档注释里写明该约定，避免再犯。

## 💾 规则引擎页新增「保存设置」

- 三个开关（启用规则引擎 / 回合末裁决卡片 / 任务契约）现在改为**草稿态**：勾选只改本地草稿，不再即时写后端。
- 页面底部新增 **「保存设置」** 按钮，**一次提交整页配置**并本地持久化（`deep-ide-rules-cfg`），启动时回填并写回后端。
- 保存成功后按钮短暂显示「✅ 已保存」，同时在日志与系统消息里记录本次保存的内容。
- 记忆页的开关仍是即时生效（带失败回滚 + 明确报错，不再静默）。
