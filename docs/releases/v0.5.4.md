## DeepAhead v0.5.4

**修掉更新时弹出的黑色 CMD 窗口，并把「开始 → 卸载 DeepAhead」做成真正的一键静默卸载。**

---

## 🐛 那个黑窗是什么

就是你看到的、标题为 `find "292"` 的那个窗口——**它是我自己的更新辅助脚本**。

上一版用的是批处理（`cmd /C deepahead-update.cmd`），内容是：

```bat
:waitloop
tasklist /FI "PID eq %PID%" | find "%PID%" >nul     ← 窗口标题就是这个 find
timeout /t 2 /nobreak >nul
...
start "" /wait "uninstaller.exe" /S
start "" /wait "setup.exe" /S
```

两个问题：

1. **隐藏没生效**：我同时传了 `DETACHED_PROCESS` 和 `CREATE_NO_WINDOW`，这两个标志语义**互相冲突**（前者=干脆不要控制台，后者=建控制台但隐藏）；而且批处理里的 `tasklist | find`、`timeout`、`start` 在 Windows 11 上会拉起 Windows Terminal 窗口——标题正好是 `find "292"`。
2. **看不到进度**：窗口一旦出现，用户会以为卡住了，其实安装正在后台跑。

### 现在的做法：无窗口 VBScript

改用 `wscript.exe` 承载脚本：

- `wscript.exe` 是 **GUI 子系统程序，从不分配控制台**——从根上不可能弹黑窗；
- 用 `//B`（批处理模式）连脚本报错弹窗都抑制；
- 等待应用退出改用 **WMI 查询**（`Win32_Process`），不再用 `tasklist | find`；
- 所有 `Run` 一律用**窗口样式 0（隐藏）**：`sh.Run "…uninstall.exe" /S", 0, True`；
- 脚本以 **UTF-16LE + BOM** 写入，中文/空格路径不会乱码。

### 过程留痕改到日志文件

没有控制台了，所以辅助脚本把每一步写进：

```
%TEMP%\DeepAhead_update\update.log
```

内容形如：

```
2026/10/9 11:25:51  app exited after 3s
2026/10/9 11:25:53  running uninstaller (silent, hidden)
2026/10/9 11:25:56  uninstaller returned
2026/10/9 11:25:56  running installer (silent, hidden)
2026/10/9 11:26:40  installer returned
2026/10/9 11:26:40  relaunching app
```

**进度条跑完 → 自动退出 → 自动卸载 → 自动安装 → 自动重启**，全程零窗口、零点击。

## 🗑 「开始 → 卸载 DeepAhead」变成真正的一键静默卸载

以前只是弹一个「请走系统控制面板」的提示。现在：

1. 弹出确认框（说明会删什么、不会删什么）
2. 确认后立刻启动**无窗口**卸载脚本
3. 应用退出 → 后台静默运行 `uninstall.exe /S` → 删除安装目录与开始菜单项

**项目文件与设置不会被删除**（它们在你的工作目录与用户数据目录里）。

## 🧹 顺手修的：临时目录不再堆积安装包

每次更新会把新安装包下到 `%TEMP%\DeepAhead_update\`。以前**旧的不会删**——我检查时发现里面已经躺着 0.5.1 和 0.5.3 两个包，共 200 MB。现在下载前会清理同目录下的旧安装包与遗留的 `.cmd` 脚本。

## 验证

新增两条**真机**测试，不是推测：

| 测试 | 内容 |
|---|---|
| `helper_scripts_never_allocate_a_console` | 断言生成的脚本里**不再出现** `cmd /C`、`start ""`、`tasklist`、`timeout /t`、`find "`、`@echo off`（黑窗元凶）；且必须含 WMI 等待、`, 0, True`（隐藏窗口）、`OpenTextFile`（日志） |
| `vbscript_syntax_is_valid_on_this_machine` | 用**同一份 header** 真机跑 `cscript.exe //B`，通过日志文件确认等待循环与正文都执行成功 |

> 这条测试还顺带发现一个事实：`cscript //B` 会把 `WScript.Echo` 的输出一并吞掉（连最小 ANSI 脚本都拿不到 stdout）。所以断言改走日志文件——这也正是生产脚本用的通道。

- `cargo test --lib` → **69 passed / 0 failed**（新增 2 条）
- `cargo test --lib -- --ignored live_gitee` → **2 passed**（真实 Gitee 网络）
- `vue-tsc --noEmit` → 0 错误
- `cargo check` → 0 错误

## 安装

下载 `DeepAhead_0.5.4_x64-setup.exe` 安装（Windows x64，NSIS 当前用户安装）。

> 用 0.5.3 及更早版本更新时会看到那个黑窗（旧代码）；装上 0.5.4 之后就干净了。
