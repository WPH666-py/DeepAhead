## DeepAhead v0.5.2

**修复：明明推送了新安装包却不弹更新提示。**

---

## 🐛 根因（我上一版引入的 bug）

0.5.0 的启动逻辑里有一处自相矛盾：`checkForUpdate()` 发现新版本后会把弹框设为显示，**紧接着**又调用了 `snoozeUpdate()` —— 而 `snoozeUpdate()` 的第一件事就是把弹框设为隐藏并武装"10 分钟后再提醒"的定时器。

```js
// 0.5.0 的错误写法
const found = await checkForUpdate();   // ← 这里弹框已设为「显示」
if (found || pending) {
  if (updateInfo.value?.has_update) snoozeUpdate();   // ← 立刻又设为「隐藏」
}
```

**实际表现**：弹框出现的一瞬间就被自己关掉，只有等 10 分钟定时器触发才会真正弹出来；如果这期间关掉了应用，就永远看不到提示。所以"推送了新安装包却没提示"——不是检测失败，而是**检测成功了但提示被自己藏了**。

### 修复

- 启动时发现新版本 → **立即展示，不隐藏、不武装定时器**，等用户自己选。
- 只有用户点击「暂不更新」时才武装 10 分钟提醒定时器（这正是上一版想要却写反的语义）。
- 上次会话遗留的待更新版本：启动时复查，仍存在就直接提示；已不存在则清除标记。
- 新增**长驻会话定期复查**（每 6 小时），挂着不关也能收到新版本提示。

## 🔄 新增「检查更新」手动入口

「AI 驾驶舱」下拉里新增一项：

```
🔄 检查更新（当前 0.5.2）
```

点击后立即检查并给出明确结果——已是最新（显示当前版本与 Gitee 最新发布）、发现新版本（弹更新框）、或失败原因。**这是排查"为什么没提示"最直接的手段。**

## 📋 检查结果现在会写进「日志」面板

以前检查失败是静默的，用户无从判断。现在无论成功、失败、还是"有新版本但发布下没有安装包附件"，都会在日志面板留痕：

- `检查更新：已是最新（当前 0.5.2）` + Gitee 最新发布
- `发现新版本 0.5.2（当前 0.5.0）` + 安装包名
- `检查更新：<失败原因>`
- `发现新版本 X` + `⚠️ 该发布下没有安装包附件，无法自动更新`

## ✅ 本轮实测（真实网络，非推测）

新增两个 `#[ignore]` 的真实网络测试并实际运行，证明 Rust 侧检测链路可用：

```
$ cargo test --lib -- --ignored live_gitee --nocapture
current=0.0.1 latest=v0.5.1 has_update=true error=None
asset=DeepAhead_0.5.1_x64-setup.exe

received 101018679 bytes      ← MZ 头校验通过
test result: ok. 2 passed
```

**结论：后端检测与下载一直是好的，问题只在前端把弹框藏了。**

## 如果你现在装的是 0.4.x

0.4.x **完全没有自动更新功能**（该功能 0.5.0 才引入），所以不会、也不可能弹更新提示。请手动安装一次 0.5.2；之后从 0.5.2 起自动更新会正常工作。
