## 🔄 自动更新

### 检测

- 通过 **Gitee 公开 API** 读取 releases：`GET https://gitee.com/api/v5/repos/{owner}/{repo}/releases`
- **无需任何凭据**（公开仓库可直接读取，已实测）——终端用户开箱即用。
- 不只是信"最新"排序：在所有发布里按**语义化版本**取最大者，容忍 `v` 前缀与 `-rc.1` 之类预发布后缀。
- 从发布的 `assets` 里优先挑 `.exe` 且名字含 `setup` 的附件作为安装包。
- 检查失败**静默**（网络异常不打扰用户），上次成功检测到的待更新版本会落盘。

### 弹框

发现新版本时弹出对话框，显示：当前版本 → 新版本、安装包名与大小、发布时间、更新说明（可滚动），以及两个按钮：

| 按钮 | 行为 |
|---|---|
| **暂不更新** | 关闭弹框，但**每 10 分钟再次提醒**，直到用户点击「立即更新」为止 |
| **立即更新** | 从 Gitee 下载安装包（带进度条）→ 启动更新 → 应用退出 → 自动卸载旧版并安装新版 → 自动重新启动 |

「暂不更新」后待更新版本写入本地存储，因此**重启应用仍会继续提醒**（10 分钟周期重新武装）。

### 更新是怎么实现的（关键约束）

Windows 上**运行中的 exe 不能被替换**，所以不能在进程内"就地覆盖"。实现方式是：

1. 下载新安装包到 `%TEMP%\DeepAhead_update\`
2. 生成一个**游离的批处理脚本**，用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW` 启动，使其脱离本进程独立存活
3. 脚本按序执行：
   ```
   等待本进程 PID 消失（轮询 tasklist）
     → 静默卸载旧版（uninstall.exe /S）
     → 静默安装新版（setup.exe /S）
     → 重新启动应用
     → 自删除脚本
   ```
4. 应用本身在启动脚本后约 0.8 秒退出

**为什么必须这样**：卸载不能在进程内做（会删掉自己的文件），安装也不能（exe 被占用）。因此"卸载 → 重装"必须交给一个独立于本进程的助手。

下载有基本校验：小于 1 MB 视为异常并丢弃。

## 🛡 规则引擎：补齐此前"未实现"的能力

### ① 文本审计与纠正注入

移植 `text-detect` / `semantic` 的主要检测器（12 项）：

| 规则 | 检测 |
|---|---|
| 7 | 承诺性表达（一定/保证/绝对/100%/guaranteed…） |
| 23 | **声称已完成但没有验证证据**（已完成/已修复/搞定…但无测试通过、cargo test 等） |
| 2 | 使用当前时间词但没有取时间证据 |
| 5 | 引用链接但没有标注来源 |
| 14 | 正文里使用路径缩写（`~/.dsh`、`%USERPROFILE%`…） |
| 22 | 空洞回应（"好的"）／只道歉不给原因与改进 |
| 16 | 同一会话第 3 次给建议（应直接执行） |
| 31 | 重复只读调用 ≥3 次且无验证意图 |
| 11 | 用户中文但回复以英文为主 |

**边界与上游一致：助手输出不可阻断**，只做审计 + 注入纠正。交付门同样保留：

- 每个 **(会话, 规则)** 只注入一次
- 每会话**每小时最多 3 次**
- 注入文本若看起来像命令则拒绝投递

注入文本形状对齐上游：`[规则引擎] <标题>（规则 N，已记入 /guard log；下次回复请自证/纠正）`，多条时聚合为"本轮检出 N 项：…"。

### ② 任务契约

完整实现 `decideContractAction` 的 reason code 体系：

```
CONTROL_INACTIVE → MODE_FORBIDS_MUTATION → MUTABILITY_UNPROVEN
→ DESTRUCTIVE_NOT_ALLOWED → WRITE_PATH_UNPROVEN / PATH_OUTSIDE_CONTRACT
→ CATEGORY_NOT_IN_CONTRACT → AGENT_BUDGET_EXHAUSTED → WITHIN_CONTRACT
```

- 模式：`observe / review / answer / change / monitor / watch / off`
- **破坏性类别（delete/move/replace/purge）结构性不可授权**——即使写进 allow 列表也会被拒
- 路径前缀约束、命令类别约束、委派预算（armed 且为 0 时按 2 处理）
- 已接入 Agent 循环：契约拒绝会生成裁决卡片并记 `task-contract-deny` 审计

### ③ 质量账本

任务签名归一化（去引号 → 绝对路径 → `<path>` → 数字 → `<n>` → 折叠空白 → 小写 → FNV-1a 前 12 位），按签名聚合**前后窗口趋势**（rework + frictions 均值），`/guard quality` 展示。

### ④ 热词学习

长度 2–12、去重、上限 500、原子写（临时文件 + rename）。学到的热词参与执行子句判定——模型确认的新动作词能让后续同类请求不再被"无执行子句"拦下。

### ⑤ `/guard` 新增 6 组子命令

```
mode <observe|review|answer|change|monitor|watch|off>

```
